# ПОС: преподавательская оценка студентов

C++20, консольное приложение. Проверено в Ubuntu 24.04 / WSL, GCC 13.
Нужны CMake 3.20+, поддержка `std::format`; тесты используют Catch2 3.5.2.

## Сборка

```sh
cmake -S . -B build
cmake --build build -j 4
ctest --test-dir build --output-on-failure
./build/hw_2
```

При первой сборке тестов Catch2 скачивается с GitHub (нужны Git и сеть).
Для сборки без тестов и скачивания зависимостей: `-DBUILD_TESTING=OFF`.
Для уже загруженного Catch2: `-DFETCHCONTENT_FULLY_DISCONNECTED=ON`.

## Команды и демонстрация

Меню сохранено: 2 — студенты, 4 — ввод команды, 5 — справка, 6 — выход.
EOF тоже завершает программу. ФИО — остаток строки после ID; названия
программ, предметов и критериев вводятся без пробелов.

| Пример команды | Действие |
| --- | --- |
| `studyProgram se` | Создать программу |
| `subject math se` | Создать предмет |
| `student 1 Ivan Petrov` | Добавить студента |
| `criterion se math exam 100 7` | Критерий: максимум 100, вес 7 |
| `criteria se math` | Показать критерии |
| `evaluate se math 1 exam 80` | Выставить или исправить оценку |
| `evaluations se math 1` | Показать оценки (`missing` — пропуск) |
| `cancel se math 1 exam` | Отменить оценку |
| `final se math 1 strict` | Итог, требующий все оценки |
| `final se math 1 zero` | Итог с нулём вместо пропусков |
| `report se math` | Итоги всех студентов, пропуски считаются нулями |
| `export se math finals.csv` | CSV; требует все оценки и новое имя файла |

Демонстрация через обычное меню: `./build/hw_2 < examples/demo.txt`.
Запускайте там, где ещё нет `finals.csv`. Сценарий показывает итог 8.30,
после отмены домашней работы — 5.60, после её восстановления — экспорт 8.60.
Имена CSV с пробелами заключаются в двойные кавычки.

## DDD, архитектура и паттерны

Entity: `Student` с идентичностью по ID и `Subject` по паре программа + имя.
`Subject` — корень агрегата рубрикатора и оценок; ключ оценки — студент + критерий.
Value Object: `EvaluationScore`, неизменяемый балл без ID, сравниваемый по значению.
`IPOSRepository` — порт хранения; `InMemoryPOSRepository` — реализация в памяти.
`FinalScoreService` — Domain Service: итог считается из текущих оценок,
`10 * sum(weight * score / maxScore) / sum(weight)`, веса могут не давать сумму 1.
Модель запрещает неизвестный критерий, балл вне диапазона, неположительный
максимум нового критерия и некорректный вес. Фасад проверяет наличие студента.

Ports and Adapters закреплена целями CMake:
`core -> pos_adapters -> pos_application -> pos_domain`.
Domain: исходные сущности, `final_score`, `include/domain/`.
Application: типизированные методы фасада и `src/application/`.
Adapters: консоль, парсер, репозиторий и `src/adapters/` (включая CSV).
Старые потоковые перегрузки фасада оставлены для совместимости, но их реализация
вынесена в адаптер; домен и прикладная библиотека не выполняют консольный ввод-вывод.
`ApplicationContainer` в `bootstrap/` — небольшой DI-контейнер: хранит общий
репозиторий и передаёт зависимости в конструкторы фасада и консоли.

Три паттерна: Factory (`EvaluationFactory`) создаёт только допустимые баллы;
Facade (`POSApplicationFacade`) объединяет сценарии; Strategy
(`IMissingEvaluationStrategy`) меняет обработку пропусков (`strict` / `zero`).
Нулевой балл отличается от отсутствующей оценки. Итог не кешируется и поэтому
согласован с исправлениями и отменой. CSV зависит от порта `IFinalExporter`.
